## 1. Утверждённая архитектура и ограничения

Поток: **Android AI-Recorder → FastAPI → faster-whisper (аудио → текст) → выбранный LLM-провайдер → Pydantic + проверка привязки к источнику → JSON для Android**.

- Сохранить существующие маршруты `GET /health`, `POST /v1/transcribe` и `POST /v1/analyze`. Не менять их контракт без отдельного согласования.
- Сохранить существующую транскрибацию через faster-whisper и функции `source_sentences()`, `ground_title()`, `ground_tasks()`.
- Ollama остаётся альтернативным провайдером; выбор `AI_PROVIDER=ollama|lmstudio`, по умолчанию Ollama. Переключение основной конфигурации **ещё не выполнялось**.
- Исходный контракт анализа: `ModelSelection` с `suggestedTitle: str`, `summary: str`, `taskSentenceIds: list[int]`; затем `ModelAnalysis` с проверенными задачами. Не заменять `taskSentenceIds` на готовый массив выдуманных моделью задач.
- Модуль `local_llm.py` вызывает LM Studio по `http://127.0.0.1:1234/v1/chat/completions` через OpenAI-совместимый API (`response_format=json_schema`); для Ollama используется иной формат ответа (`done`, `done_reason`, `message`).
- Защищать приватность: модель и API работают локально; не публиковать ключи, приватные пути, IP-адреса и персональные аудио. Доступ с LAN не включать без отдельной проверки.
- Разработка Android — Java. Изменения в рабочий код — отдельной веткой и PR на подтверждение. STAGING/тестовую конфигурацию не считать production.

## 4. Ошибки, причины и постоянные правила предотвращения

1. **Кириллица превратилась в `????`.** Передача русскоязычного исходного Python через PowerShell-конвейер (`@'...'@ | python -`) могла повредить символы в Windows PowerShell 5.1. **Правило:** записывать скрипты в UTF-8 файлы (`Set-Content -Encoding UTF8`), запускать файл Python напрямую; контрольный тест — сохранность кириллицы до обращения к LLM.
2. **`elseif` / `else` интерпретировались как отдельные команды.** Многострочный блок вставлялся в PowerShell по частям. **Правило:** цельные сценарии в `.ps1` или `.py`; один запуск; идемпотентность и синтаксическая проверка; не просить пользователя вводить разрозненные ветви условного оператора.
3. **`record_id` отправлялся UUID, сервер вернул HTTP 422.** Поле API ожидает **целое число**, не UUID. **Правило:** перед построением multipart-запроса инспектировать OpenAPI не только по `required`, но и по типам полей.
4. **WAV вместо M4A дал HTTP 415.** Сервер принимает файл с расширением `.m4a`; переименование WAV недостаточно. **Правило:** генерировать настоящий AAC в контейнере M4A (например, PyAV), отдельно проверять декодирование; при отправке `multipart/form-data` включать `file` и числовой `record_id`.
5. **Автопоиск бинарного поля не обнаружил `file`.** Вывод OpenAPI перечислил `required=['record_id','file']`, но старый скрипт рассчитывал только на `format=binary`. **Правило:** проверять всю схему запроса, её `$ref`, типы и именованные параметры; не объявлять Backend неисправным из-за ограничений тестового генератора.
6. **:8000 недоступен, хотя :8001 исправно работал.** **Правило:** разделять процессы и конфигурации; не считать результаты `health` одного порта свидетельством состояния другого. Не поднимать/переключать основной сервис до проверки и согласования.
7. **Нельзя просто заменить Ollama URL на LM Studio.** Форматы payload/response различаются. **Правило:** изолированные адаптеры, единая `ModelSelection`-валидация, проверка `finish_reason`, тайм-ауты, ограничения размера ответа и консервативная обработка ошибок.
8. **Не объявлять PASS без выполнения.** PASS/FAIL/SKIP — только реальные результаты; отсутствие E2E-теста не означает успех. Результаты теста локального оборудования получает и сообщает владелец, ассистент их не выдумывает.

## 5. Рабочий порядок

- Ассистент выполняет анализ, готовит код, тесты, документацию, отдельные ветки/PR и самостоятельно проверяет всё, к чему имеет доступ.
- На Windows-пользователя возлагается **минимум действий**, только когда нужен доступ к `localhost`, устройствам или локальным файлам. Вместо ручных повторений — один комплексный скрипт и единый отчёт. Не архивировать скрипты без запроса.
- Не делать повторно подтверждённые проверки без конкретной причины. При новом сбое диагностировать ровно отказавший этап.
- До перехода в production — отдельные испытания и явное подтверждение владельца; изменения Android API и рабочей транскрибации не предполагать.
- Локальные результаты и файлы Python не автоматически коммитятся в Android GitHub-репозиторий. Перед синхронизацией получить фактический diff/состояние и исключить секреты, кэши, venv и локальные адреса.

Расхождения `Get-NetTCPConnection`/`netstat` и HTTP требуют аккуратной интерпретации и не оправдывают новые перезапуски.
- Пары родитель/дочерний процесс объясняются запусками Uvicorn с `--workers 1`: Uvicorn имеет управляющий процесс и worker и в Windows использует `spawn`. Справка: https://uvicorn.dev/deployment/ и https://uvicorn.dev/settings/ .
- **Исправление предыдущего вывода:** PID 5064 существовал как управляющий процесс локального сервера (из раздела 7), хотя ранее не считался владельцем TCP-сокета. PID 5892 относится к LAN FastAPI. Проверка только одного PID или только строки LISTENING в `netstat` не является надёжным признаком здоровья FastAPI. Для контроля использовать `/health` целевого адреса и фактическую командную строку соответствующей пары процессов.
- Измерения подтверждают **три одновременно работавших экземпляра Uvicorn** с разным назначением. Это избыточно для обычного использования на одном домашнем телефоне, но **самостоятельно не доказывает утечку ресурсов или аварийные рестарты**.
- **Следующее решение:** проектировать управляемый LAN-сервис с одной точкой запуска, логом и идентификацией родительского процесса, устранять лишние экземпляры только после согласования режима, не затрагивать рабочий анализ с телефона. Автозапуск и закрытие лишних портов пока не реализованы.

## 23. Утверждён новый провайдер: Google Gemini API (2026-11-04)

**Решение владельца:** добавить в AI-Recorder доступ к облачным моделям Gemini через API Google AI Studio.

**Архитектурное решение до проверки:** Android → существующий FastAPI → существующий faster-whisper → переключаемый провайдер анализа `ollama|lmstudio|gemini` → Pydantic `ModelSelection` → `ground_title/ground_tasks` → существующий `ModelAnalysis` JSON для Android. Android APK, Room, M4A-контракт и маршруты не изменять.

- Выбран кандидат для первоначальной пробы: **`gemini-3.5-flash-lite` (стабильная модель)**, подходящая для структурного извлечения данных из коротких заметок. После тестов сравнить качество с Qwen3. Источник модели: https://aistudio.google.com/docs/models/gemini-3.5-flash-lite .
- Использовать документированный **Interactions API** (`POST https://generativelanguage.googleapis.com/v1beta/interactions`, заголовок `Api-Revision: 2026-05-20`) и структурированный `response_format={"type":"text","mime_type":"application/json","schema":...}` либо официальный Google GenAI SDK; не переносить без адаптации прежние Ollama/LM Studio форматы запроса. Документация: https://aistudio.google.com/docs/get-started .
- Для тестирования допускается **один короткий синтетический текст**. Существующие записи пользователей, транскрипты и M4A **не отправлять в Google до отдельного принятия облачного режима**.
- API-ключ создавать в Google AI Studio; передавать только серверу через `GEMINI_API_KEY`. Никогда не добавлять в APK, репозиторий, файл журнала, вывод консоли или чат. Источник: https://aistudio.google.com/docs/api-key .
- Важно: с 28 мая 2026 года новые ключи в AI Studio создаются как authorization keys; старые неограниченные standard keys блокируются. Использовать актуальный ключ проекта.
- Никакой автоматической отправки приватных аудио или скрытого перехода на Gemini: облачный анализ — отдельный **явно выбранный режим**, провайдер по умолчанию пока `ollama` на уровне main.py, текущие запущенные процессы могут использовать `lmstudio`. Отказ/429/квоты/тайм-ауты возвращать безопасно, не объявлять ложный успех; не делать автоматический fallback в облако.
- Доступность API, стоимость/квоты и результат реального Gemini JSON **не проверены** без пользовательского API-ключа. Billing / free tier / политика обработки данных зависит от конкретного проекта и условий Google.
- Следующий шаг: без изменений Backend, выполнить один изолированный облачный запрос через существующий Python/httpx с полностью синтетическим текстом, проверить JSON/Pydantic и `taskSentenceIds`. Только после PASS готовить отдельный Gemini-адаптер и протестировать его на новом тестовом процессе перед включением в основной FastAPI.
