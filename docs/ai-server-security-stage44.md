# Этап 44 — защита LAN API и контролируемый выбор Gemini/Qwen3

**Статус: подготовлено к ревью, НЕ активировано.** Основание — ветка Android `feature/ai-agent-stage5`. Рабочий FastAPI, Android APK, Windows Firewall и выбор `AI_PROVIDER` не изменены.

## Результат аудита
- В `RemoteAiProcessor.java` запрос `POST /v1/analyze` передаёт числовой `record_id` и M4A, но **не содержит авторизации**.
- Debug-сборка разрешает HTTP на выбранный частный IPv4; это не шифрование и не проверка личности клиента.
- На тестовом FastAPI Gemini анализ синтетического M4A успешно прошёл HTTP 200, запись и 2 задачи. **Облачный режим для реальных аудиозаписей не разрешён автоматически**.
- Локальный `main.py`/Gemini adapter находятся на ПК владельца и не представлены в этом Android-репозитории. Код, добавленный в PR, не включён в рабочий сервер.

## Двухэтапное внедрение без остановки телефона
1. **HTTPS:** сначала настроить проверяемый TLS для телефона → FastAPI. Не обходить проверку сертификата и не включать HTTP глобально. Для Android debug Network Security Configuration поддерживает специальные доверенные сертификаты.
2. **Подлинность устройства:** спаривание телефона с сервером и выдача **индивидуального отзываемого** токена. Пользовательский секрет не в APK, Gradle, `BuildConfig`, Git или логах; хранить его в Android Keystore, выдавать через доверенный канал. Запросы проверяются сервером.
3. **Раздельное согласие:** право устройства вызывать `/v1/analyze` не означает разрешение передавать данные в Gemini; облачный режим должен быть явно выбран. По умолчанию рабочий сервер продолжает Qwen3/LM Studio.
4. **Тестовый ввод:** включать защиту только на отдельном HTTPS тестовом FastAPI; проверить 401/403/200 и ошибки TLS с новым Android, затем переносить на рабочий LAN.
5. **Откат:** до изменения LAN создать резервные копии конфигурации и проверить выключение нового режима без смены провайдера и потери сохранённых результатов.

## Неактивный компонент FastAPI
`backend_security/lan_auth.py` — изолированный ASGI `LanAuthGuard`:
- `enabled=False` по умолчанию; текущие запросы остаются без изменений.
- `enabled=True` требует `AI_LAN_API_TOKEN` (32–256 байт) из окружения, иначе отказ при старте; не публикует секрет.
- Защищает `/v1/analyze` и `/v1/transcribe`, не читает загружаемое аудио.
- По HTTP отвечает `403 AI_TLS_REQUIRED`; без верного токена через HTTPS — `401 AI_AUTH_REQUIRED`. Сравнение секретов через `hmac.compare_digest`. `/health` остаётся техническим.
- Это **прототип одного Bearer-токена**, а не завершённая система регистрации/отзыва устройств. **НЕ подключать его к текущему `main.py`** до реализации HTTPS и выдачи персональных учётных данных.

**Предупреждение о reverse proxy:** `scope['scheme']` должен отражать действительное TLS-соединение с доверенным ingress. Клиентскому `X-Forwarded-Proto` доверять нельзя; backend за proxy нужно привязать к loopback и настроить доверенные proxy-адреса.

## Проверка
В среде ассистента проверена функционально идентичная версия модуля с FastAPI TestClient:
```
pytest -q tests/test_lan_auth.py
8 passed
```
Сценарии: текущий HTTP без включения защиты, отсутствие ключа, отклонение HTTP при валидном токене, отсутствие/неверный токен, правильный токен через HTTPS, доступность /health, невозможность подделать HTTPS через X-Forwarded-Proto. **Это не результат теста на ПК владельца**.

## Критерии принятия полноценной реализации
- TLS с проверкой сертификата; ни одного секрета в APK; индивидуальная выдача и отзыв.
- Отрицательные и положительные HTTP интеграционные тесты; никаких повторных POST из-за ошибки авторизации.
- Сохранены текущий M4A-контракт, Room, проверка taskSentenceIds/ground_tasks и Qwen3 по умолчанию.
- Реальный тест телефона под новым транспортом и подтверждение, что Gemini не используется без явного выбора.
- Документированный rollback; GitHub PR обсуждается и сливается только после подтверждения владельцем.
